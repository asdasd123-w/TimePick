# 拾光 TimePick · 作品介绍

> 一款把「记录过去的文字」变成「可以走进去的空间」的记忆管理应用。
> 网页端（Vue 3 + Express + SQLite）＋ 3D 记忆房间（Cocos Creator 3.8.8）。

---

## 一、项目说明

### 1.1 一句话

把每一条生活记忆存进一座**记忆岛**，再用一座**可以推门走进去的 3D 房间**把这些记忆重新看见。

### 1.2 目标用户

| 用户 | 痛点 | 拾光怎么解决 |
|---|---|---|
| 有记录习惯的学生 / 年轻上班族 | 日记、照片散落在相册、备忘录、社交平台，写完就不会再看 | 按主题聚成"记忆岛"，配封面、日期、影像，一眼看到那段时光 |
| 喜欢仪式感的人 | 普通列表式日记没有"回去看看"的吸引力 | 3D 房间把记忆做成可摆放、可触摸的家具与装饰 |
| 想分享又怕暴露隐私的人 | 朋友圈发出去就收不回 | 每条记忆独立控制公开与否，公开的才进"拾光广场"；删除动态只取消公开、不删记忆 |

### 1.3 核心使用流程

```
注册（手机号 + 口令）
   → 建一座记忆岛（选主题、封面）
      → 写一条记忆（正文 + 图片/视频/音频 + 日期）
         → AI 自动取 2~4 字标题、生成封面
            → 选择「只自己看」或「分享到广场」
               → 进入这座岛的 3D 房间，把记忆摆进房间
```

### 1.4 功能清单

| 模块 | 功能 |
|---|---|
| 账号 | 手机号注册/登录、注册口令校验、微信扫码登录、找回密码、昵称头像、隐私设置、账号注销 |
| 记忆库 | 记忆岛（新建/改名/删除/容量上限）、记忆条目（正文/多图/视频/音频/日期）、AI 标题、AI 封面、置顶、收藏、点赞、评论、按岛筛选、搜索 |
| 拾光广场 | 动态流、发布（与记忆库同一套落库逻辑）、点赞、评论、话题标签、举报、共享记忆、推荐记忆空间（按粉丝/条数/点赞推荐其他用户） |
| 活动 | 活动列表与详情、报名/取消报名（实时同步统计）、活动评论、活动点赞 |
| 社交 | 关注/粉丝、私信（含未读数、会话列表）、通知中心 |
| 3D 房间 | 岛屿俯瞰、进入房间、家具摆放与旋转、宠物陪伴（5 种花色）、背景音乐、访客足迹、房间内的记忆展示 |
| 管理中心 | 用户管理（改昵称/重置密码/禁用/删除/设管理员）、活动管理、内容审核（举报）、通知发布、AI 使用总开关与用户级权限、AI 密钥管理、数据导出/导入 |
| 权限 | 超级管理员保护（不可删除/不可禁用/不可取消/密码不可重置）、AI 密钥仅超管可改 |

页面共 24 个 Vue 组件，路由主入口 10 个：`/`（首页）、`/index`（记忆库/广场/个人中心/管理中心的父级）、
`/room/:spaceId`（3D 房间）、`/share/:token`（分享页）、`/privacy`、`/feedback`。

## 二、AI 能力说明

三类模型各司其职，全部由**服务端代理**调用，密钥永不下发到浏览器：

| 能力 | 模型 | 作用 | 失败时的降级 |
|---|---|---|---|
| 文字生成 | **DeepSeek**（`deepseek-chat`） | ① 从记忆正文提炼 2~4 字标题 ② AI 润色（记忆正文/活动文案/通知） ③ 小橘 AI 陪伴对话 ④ 为封面生成画面描述 | 取标题退回"正文前 12 字"；润色原样返回；对话提示稍后再试 |
| 图像生成 | **智谱 CogView**（`cogview-3-flash`） | 根据 DeepSeek 写的画面描述生成记忆封面（1344×768） | 保留用户自选封面或纯色占位 |
| 视频生成 | **阿里云百炼 · 万相**（`wan2.2-i2v-flash`） | 以一张图片生成 5 秒动态回忆视频 | 提示额度/网络问题，不阻塞发布 |
| 语音识别 | **阿里云百炼 ASR** | 录音转文字，用于口述记忆 | 提示可手动输入 |

设计与工程要点：

1. **密钥只在服务端**。前端一律调用 `/api` 的 `ai/chat`、`ai/cover`、`ai/video` 代理接口，
   `.env.production` 里只有一行 `VITE_CLOUD_API_BASE=/api`，构建产物里搜不到任何密钥。
2. **密钥可热更新**。超级管理员在「管理中心 → AI 使用」里改密钥，写入 `app_secret` 表并在内存中刷新，
   **不重启、不重新部署**立刻生效；清空则回落到 `.env`。同时页面只显示掩码（`sk-7••••••a067`）
   和来源（"后台设置"/"来自 .env"），并提供每一栏"这条密钥控制哪些功能"的说明。
3. **配额与开关分层**。全站总开关（`system_config`）+ 用户级开关（`user.ai_chat / ai_image`），
   级联规则在服务端算好：开生图自动开对话，关对话则生图/生视频一并关。
   另有每日视频生成上限（默认 10 条/人）。
4. **失败不阻塞主流程**。AI 是增强项，任一路失败都退回基础能力，用户照常能写完一条记忆。

## 三、创新点

| 维度 | 内容 |
|---|---|
| 场景创新 | 记忆不是"列表"，是"岛屿 + 房间"。同一条记忆在列表里可检索、在房间里可触摸，两种心智模型互补 |
| 数据模型创新 | **广场动态与记忆条目是同一份数据**：发布先落 `memory_item`，再用 `square_post.memory_id` 单向绑定投影。改一处两处同步，删除动态只把 `is_public` 置 0、不删记忆——避免了"发到广场后记忆库里找不到"的割裂感 |
| 体验创新 | 3D 首屏需要加载约 130 MB 资源（20 秒以上），期间提供**可玩的跑酷小游戏 + 真实下载进度条**，把等待变成体验的一部分 |
| 产品创新 | 权限做了"最高权限不可篡改"的设计：超级管理员不可被删除/禁用/取消/重置密码，且其密码对任何管理员都不可见——防止管理员互相夺权 |
| 技术创新 | SQLite **三级驱动兜底**（原生 → Node 内置 → 纯 WASM），同一份代码在能编译和不能编译的机器上都能跑；单端口同源部署（Express 同时托管前端 + API + SPA 兜底），一台最小规格服务器即可承载 |
| 运维创新 | AI 密钥运行时可改、数据可导出/导入（含密码哈希），把"改配置要重新部署"和"发布冲掉线上数据"两个常见事故点提前堵住 |
| 适配创新 | 桌面版是「固定比例海报 + 百分比定位热点」，直接缩放会让手机上的按钮只剩 18px。解法不是做一套移动版，而是**在小屏解除海报的容器查询、让控件回到文档流**，桌面的像素级版式一行不动（逐元素矩形与改动前完全一致） |

## 四、技术实现

### 4.1 架构

```
                    ┌──────────────────────────────────────────┐
   浏览器 ──────────▶│  Express 5（单端口 8787）                 │
                    │                                          │
   页面 /index/*    │  ① 静态托管 dist（SPA 兜底 → index.html） │
   /api  ──────────▶│  ② 接口层：65+ 个 action 分发             │
   /uploads ───────▶│  ③ 上传文件静态服务                       │
                    └───────────────┬──────────────────────────┘
                                    │
                    ┌───────────────▼──────────────────────────┐
                    │  SQLite（28 张表，单文件 timepick.db）    │
                    │  better-sqlite3 → node:sqlite → WASM      │
                    └──────────────────────────────────────────┘
                                    ▲
                    ┌───────────────┴──────────────────────────┐
                    │  外部 AI：DeepSeek / 智谱 CogView /        │
                    │  阿里云百炼（万相 i2v、ASR）               │
                    └──────────────────────────────────────────┘

   3D 房间：前端 iframe 加载 Cocos 产物 /room3d/
            iframe ⇄ 宿主 通过 postMessage 通信（tp:ready / tp:progress / tp:pick …）
```

### 4.2 技术选型

| 层 | 选型 | 为什么 |
|---|---|---|
| 前端框架 | Vue 3.5（`<script setup>`）+ Vue Router 5 + Pinia 4 | 组合式 API 适合把"记忆/广场/房间"这类跨页状态拆成 store；单文件组件写样式最快 |
| 构建 | Vite 8 | 冷启动秒级，构建 30~60 秒；`emptyOutDir: false` 避免误删正在用的产物 |
| 后端 | Node.js + Express 5（ESM） | 与前端同语言，一个人能维护全栈；单入口 RPC 式分发（`{action, params}`）比 65 个 REST 路由更好做统一鉴权与限流 |
| 数据库 | SQLite | 零运维、单文件、易备份；本项目数据量（万级）完全够用 |
| 3D | Cocos Creator 3.8.8 + TypeScript | 场景编辑器成熟，glTF 模型导入顺畅，Web 端产物体积可控 |
| 部署 | 单端口 + 平台托管 | 一份 `node server/index.js` 即可，不需要 Nginx/PM2 |

### 4.3 关键难点与解法

**① 发布时数据库被覆盖（真实事故）**

平台发布是"清空目标目录再上传整个项目"，而项目里带着 `server/data/timepick.db`，
于是每次发布都会把线上库换成本地快照——一次真实发布中，线上注册的账号与记忆全部丢失。

解法：新增 `admin/data/export` / `admin/data/import` 接口，发布流程固定为
**导出线上数据 → 发布 → 回灌数据**（走 replace 模式，含密码哈希，账号可原样恢复），
并在运维脚本里加告警。此后多次发布均验证数据完整。

**② 同一个功能两处状态不同步**

活动卡片与详情弹窗是两个对象，点"加入"只改了被点的那份，关掉弹窗后统计还是旧值。
解法：按 id 同时在两处更新（详情与列表），刷新后以服务端返回的 `isJoined/joined` 为准。

**③ 广场发布与记忆库割裂**

原实现广场发布只写 `square_post`，记忆库里看不到这条内容。
解法：把发布表单改成与记忆库同一套（选岛 + 正文 + 媒体 + 日期），先 `memory/item/create`、
再 `square/post/create` 绑定 `memory_id`；编辑时两处改的是同一条，老动态自动补绑定。

**④ 3D 首屏加载 20 秒以上，且"有两个加载页"**

Cocos 产物自带一个加载页，宿主页面又有一个，用户会先看到一个再看到另一个。
解法：Cocos 侧只保留一个隐藏节点 + 进度上报脚本（`postMessage`），界面统一由宿主渲染；
进度按"Resource Timing 按 URL 累加 + 拦截 XHR 的 progress 事件"取真实字节，
再叠一条平滑曲线兜底（大文件传输途中数字会停），封顶 92%，收到 `tp:ready` 补满。

**⑤ 跑酷小游戏的帧时间戳为负**

浏览器 `requestAnimationFrame` 回调收到的时间戳可能早于调度时的 `performance.now()`，
`dt` 为负 → 分数变成 "-1 分"，帧索引为负 → `undefined is not iterable` 直接抛错。
解法：`dt` 夹到 `[0, 3]`，帧索引双取模，`st.t` 不允许小于 0。

**⑥ 服务器编译不了原生模块**

`better-sqlite3` 需要 node-gyp 编译，部署沙箱拉不到 Node headers、也没有 Python。
解法：把它和 `sharp` 放进 `optionalDependencies`（装失败只警告不中断），
运行时由 `db-driver.js` 三级兜底落到纯 WASM 版 SQLite，对外接口一致。

**⑦ 桌面版式在手机上退化成"点不到"**

记忆库、隐私、个人页用的是**固定比例海报**：`container-type: size` + `min(100cqw, 100cqh*W/H)`
算出 contain 盒，控件按百分比定位。这在桌面很稳，但 390 宽的手机上整个盒子被压到 190px 高，
里面的按钮只剩 18px——看着没坏，实际手指点不中。

解法：小屏下把容器查询整块解除，卡片回到文档流、单列整宽，海报改为顶部 124–148px 装饰条
（用 `object-position` 只取插画里没有烤进标题的那一段，再加底部 mask 渐隐）。
桌面代码不写任何 if，靠一条断点隔开，**1440×900 下逐元素矩形与改动前完全一致**。

过程中撞到三个"看着该生效却没用"的坑，都记在项目笔记里：

- 断点块放在 `<style>` 中段会被后面的基础规则按"同优先级靠后覆盖"反压，
  写了等于没写（`square.vue` 的 `.p-avatar` 就被打回 34px），必须放到样式表末尾；
- 欢迎页背景是 2000×1125 横图，竖屏 `cover` 后 `left` 是很小的负数，
  任何按图片百分比定位的元素都会跑到屏外——标题因此整块消失，改为按视口锚定；
- `.post` 上的 `content-visibility: auto` 等于 paint containment，会自成层叠上下文，
  卡片内的下拉菜单用 z-index 打不过外面的遮罩，只能靠 document 事件关闭。

**⑧ 2D 宠物的位置更新一跳一跳**

原实现把"换帧"和"移动"塞进同一个 33ms 定时器，非空间页只有 15fps 更新坐标；
坐标又放在 `reactive` 里，每帧都触发一次组件渲染。

解法：坐标改成普通对象、由 `requestAnimationFrame` 直接写 `transform: translate3d`，
不走响应式；换帧用 `setTimeout` 自排（静止时按 `holdMs` 睡够再醒，不占 rAF）；
移动结束就停掉 rAF。精灵图从 1536×2288 降到 512×763（体积 4.1 MB → 523 KB），
逻辑帧坐标不变，模糊的 `drop-shadow` 换成一层静态椭圆阴影。
实测多数页面主线程耗时从 21–43 ms/s 降到 2–8 ms/s。
